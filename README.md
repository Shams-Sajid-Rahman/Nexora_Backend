# Nexora Backend

FastAPI + SQLAlchemy 2.x + Pydantic v2 + Alembic + PostgreSQL + Redis + Celery.
Modular monolith — see `../docs/01-architecture.md` and `../docs/04-database-design.md`.

## Run locally

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Configure (placeholders in ../.env.example — never commit a real .env)
cp ../.env.example .env   # then edit DATABASE_URL, JWT_SECRET, etc.
# Or export directly:
export DATABASE_URL="postgresql+psycopg://nexora_user:CHANGE_ME@localhost:5432/nexora"
export JWT_SECRET="a-long-random-secret"

alembic upgrade head
python -m app.db.seed   # demo company + admin@nexora.demo / Admin123! (change immediately)
uvicorn app.main:app --reload --port 8000
```

API docs: http://localhost:8000/docs — OpenAPI at `/api/v1/openapi.json`.
Health: `GET /health`, readiness: `GET /health/ready` (database + Redis).

## Celery worker

```bash
celery -A app.worker.celery_app worker --loglevel=info
celery -A app.worker.celery_app beat --loglevel=info
```

## Tests (no live Postgres needed)

```bash
pytest
```

Tests use SQLite in-memory (`tests/conftest.py`) with the seeded demo
company. They cover: auth login/refresh rotation/reuse, RBAC 403,
cross-company 404, unbalanced-journal rejection, journal idempotency,
stock ledger + negative-stock rejection, payroll calculation and the
approval gate for payslips.

## Structure

```
app/
  main.py            # FastAPI app, CORS, /health, error envelope (docs/06)
  core/              # config, security (bcrypt + JWT), deps, errors, logging, audit
  common/            # pagination, serializers, company-scoped CRUD helpers
  db/                # Base, session, seed (demo company + chart of accounts)
  modules/           # core, hr, payroll, inventory, purchase, sales,
                     # finance, projects, support, reports, workflow, ai
                     # each: models.py, schemas.py, services.py, routers.py
  worker.py          # Celery tasks: report export, payroll, notifications, AI
alembic/             # env.py + versions/0001_initial.py (autogenerated)
tests/               # pytest, SQLite in-memory
```

## Conventions

- Response envelope: `{"data": ..., "meta": ...}` for success,
  `{"error": {"code", "message", "details"}}` for errors (docs/06).
- Active company: `X-Company-Id` header, validated against membership
  on every request. A record from another company returns **404**;
  a missing permission returns **403**.
- Money is `NUMERIC(19,4)`, never float. Currencies: BDT, USD, EUR, GBP.
  Posted documents keep an `exchange_rate_snapshot` / `base_amount`.
- Posted journals are immutable — correct them with a reversal entry.
  Unbalanced journals are rejected with 409 `JOURNAL_UNBALANCED`;
  closed periods with 409 `PERIOD_CLOSED`.
- `stock_movements` is append-only; balances update in the same
  transaction. Negative stock is rejected unless the company enables
  `allow_negative_stock` in its settings.
- A quotation is not a sale and a sales order is not revenue — revenue
  is recognised only when an invoice is posted.
- AI: provider abstraction only (`app/modules/ai/providers.py`).
  No LLM is configured by default (`LLM_PROVIDER` empty → NullProvider).
  AI tools are read-only and permission-checked; AI never posts,
  approves or modifies salaries. All AI output is labelled AI-generated.

## Limitations / notes

- `knowledge_chunks.embedding` is JSON, not pgvector. On PostgreSQL
  with pgvector, replace it with `Vector(1536)` in Phase 15 when the
  embedding model is chosen (see docs/04).
- `finance.trial_balance` and AI forecasting use SQLite-compatible
  aggregation in tests; on PostgreSQL the monthly grouping in
  `ai/services.py` falls back to a Python grouping.
- Rate limiting is not yet wired (planned hardening in Phase 16);
  login already uses generic errors and refresh-token reuse detection.
- No production deployment is configured (per project instructions).
